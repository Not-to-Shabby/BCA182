--- v7 retraining recipe (wave-2 corpus merge vs domain shift) ---
goal: lift the v6 shipped model's frozen-test cry recall (0.345, F1 0.483, confuser FP 9.6%) under the
immutable frozen protocol (test = 40 ESC-50 crying_baby clips + frozen fold-5 non-cry;
tuning on VAL only; no ESC-50 crying_baby clip is ever trained on).
root cause addressed this wave: wave 1 could only AUGMENT close-mic donateacry cries to look
distant; wave 2 adds corpora that CONTAIN the deployment domain - 17,730 new cry clips
including real distant/room recordings (960 CSIBE AIBO room cries, 4,552 CryCeleb distant
room cries) + 43,718 new domestic non-cry clips, merged by prep_v2.py with md5
content-hash dedup against every existing split (see the prep report below).
levers: (1) merged train split (~19k cry / ~44k non-cry clips) with real distant audio, (2)
the v5 wave-level augmentation of TRAIN windows only (augment.py, same seeds) at 1 variant
per cry clip (far larger base) + 0.5 non-cry calibration fraction, with the v7 recipe
split: close-mic donateacry cries keep the FULL cry recipe (reverb/lowpass/real-noise - they
need the channel simulated) while the wave-2 cries are ALREADY distant/room recordings and get
the MILD recipe (noise+volume only) - double-degrading domain-matched audio blurred the cry
template into the siren/rooster confuser region (v7 dev run measurement), (2b) sample_weight
x3.0 on the 18 nearest loud-mechanical/animal ESC-50 train categories (the confuser
categories are in NO training split by protocol, so the noncry boundary is pushed outward
around them via their nearest in-train relatives; diagnostics diag_v2.py E1..E23), (3) seeded
model-type sweep rf16x7 / rf24x6 / rf30x8, (4) cry-vote-share threshold
    swept 40..90 with the 10% FP gate on the CONFUSER split (the task's target metric); the raw VAL
non-cry FP rate is reported at every sweep point (it runs higher: fold-4 ambience covers all 40 ESC-50 classes plus
the new hard-negative domestic classes, while the confuser split and the frozen-test non-cry subset are the deployment-relevant FP populations).
augmentation real-noise pool stays ESC-50 folds 1-3 only (identical to the v5/v6 pool so cached augmented windows stay valid; merged non-cry clips are NOT added to the pool).
augmentation (train cry windows): REAL ESC-50 fold 1-3 non-cry ambience mixed at SNR 10-25 dB (p=0.5, cry dominant; white/pink synthetic noise SNR 5-20 dB otherwise), 2-3-tap room reverb (p=0.7), first-order lowpass 2500-7000 Hz (p=0.6), volume -6..+14 dB with a +10..+20 dB loud branch (p=0.3, mirrored on non-cry), pitch/speed +/-10% (p=0.5, per file), 50 Hz hum -32..-22 dB rel (p=0.25)
augmentation (train non-cry windows): synthetic noise + volume only (same loud branch), 50% of windows
variants per cry clip: 1 (cached in features_aug_cache.npz, seeded per file)
threshold tuning uses a stress-val cry proxy: the deployment channel (always lowpass 2.5-5 kHz, real-noise mix SNR 0-10 dB) applied to VAL cry windows only - cry-side F1 mixes raw + stress val cries, the FP gate stays on raw VAL non-cry + confusers
firmware rule replicated: cry iff strict majority votes CRY AND cry vote share >= threshold (src/cry_task.c)
