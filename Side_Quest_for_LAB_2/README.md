# RT-Spark Embedded MIDI Karaoke Player (Side Quest for Lab 2)

An embedded, standalone **MIDI Karaoke Player** with real-time **Yamaha FM Synthesis (OPL3/DX style)**, ST7789 240x240 IPS display rendering, and 3.5mm headphone audio output via Everest Semiconductor ES8388 on the **RT-Thread RT-Spark (STM32F407ZGT6)** development board under **Zephyr RTOS**.

---

## 1. Project Overview & Features

- **Synthesizer Engine:** Embedded **70-voice** 3-tier **6-operator (DX7) / 4-operator (OPL3) / 2-operator (OPL2)** hybrid FM synthesizer at 44.1 kHz stereo utilizing STM32F407 Core-Coupled Memory (DTCM / CCM RAM at `0x10000000`) for zero-wait-state voice rendering. Operators support all **8 Yamaha OPL3 / TX81Z waveforms** (Sine, Half-Sine, Full-Wave / Absolute-Sine, Quarter-Sine, Alternating-Sine, Camel-Sine, Square, and Logarithmic Sawtooth) evaluated via branchless table pointer lookups. Each note has its own modulation-index envelope, per-voice **Dynamic Low-Pass VCF** (`yamaha_fm_set_vcf()`, which smoothly warms decaying piano, guitar, and brass tails), and keyboard rate scaling (-2.5 dB/octave above E4 to prevent upper-octave metallic harshness). It maps all 128 General MIDI programs onto 53 patches and follows velocity, channel volume (CC7), expression (CC11), pan, sustain pedal, pitch bend with RPN range, and the mod wheel. The sequencer ticks on its own thread and hands notes to the audio thread through a ring buffer. Every event carries the audio frame at which it must sound (the sequencer runs 40 ms ahead and the lyrics are held back by the same time), so a late wake-up of the sequencer thread no longer moves a note: on the PC bench the timing jitter of drum hits fell from about 3.5 ms RMS to 0.4 ms. Each channel mixes on its own bus with automatic sidechain accompaniment ducking (-2.5 dB while the lead vocal/melody channel is actively singing, releasing smoothly during vocal rests), an **8-line Householder FDN concert hall reverb**, a **4-phase Roland Dimension-style quadrature stereo chorus**, and a mastering stage comprising a 2-band Sub-Bass Warmth (+2.5 dB @ 95 Hz) and Air (+2.0 dB @ 6 kHz) equalizer, a feed-forward compressor with downward expander gate, a 1.4 ms look-ahead limiter, and **1st-order high-pass noise-shaped TPDF dither** at the 16-bit DAC output. `yamaha_fm_set_effects_level(0)` turns the reverb and chorus off. Twenty-six key patches (Pianos, Electric Pianos, Guitars, Basses, Strings, Violin, Cello, Choir, Pad, Brass, Sax, and Synth Leads) use **3-tier dynamic operator scaling**: full **6-operator triple-pair DX7 synthesis** (`(Op2 -> Op1) + (Op4 -> Op3) + (Op6 -> Op5)`) when $\le 12$ voices are active, **4-operator dual-pair OPL3 synthesis** when $13\text{--}22$ voices are active, and **2-operator synthesis** above 22 voices, keeping CPU load comfortably within the 220 MHz budget. `yamaha_fm_set_third_operator(false)` switches it off, and `THIRD_OP=0` does the same for `tools/synth_bench`. Songs stream from the SD card through a 512-byte read-ahead window per track (up to 64 tracks), so file size is limited by the card, not by RAM; lyrics and the lead-melody channel are found by a scan when the song loads. `tools/synth_bench/run.py` renders the real synth on the PC to WAV files and prints measurements.
- **240 MHz Clock Overclock:** The STM32F407 core runs at **240 MHz** (+43% overclock over the stock 168 MHz) via HSE 8 MHz with PLLM=8, PLLN=480, PLLP=2, PLLQ=10, which also puts the SDIO/RNG clock at exactly 48.0 MHz. Flash latency is configured at 7 wait states with ART instruction/data cache and prefetch active. APB1 runs at 30 MHz (/8) and APB2 at 60 MHz (/4). The audio rendering cycle budget per 5.8 ms buffer increases from 975,238 to **1,393,197 cycles**. On Poker Face (#63150, 214 s) the average render load fell from 68.3% at 230 MHz to 65.1% at 240 MHz with no overruns at either clock.
- **General MIDI & Yamaha OPL4 (YMF278B) Hybrid WaveTable Rhythm Kits:** Supports standard General MIDI instrument families plus a **Yamaha OPL4-style 16-bit 22.05 kHz PCM WaveTable drum engine** on MIDI Channel 10 (`include/opl4_drum_samples.h`, 85.3 KB in Flash, 0 B RAM) generated by `tools/gen_opl4_drums.py`. Features 16.16 fixed-point linear-interpolated PCM playback for Acoustic Kick, Snare, Rimshot/Side Stick, Multi-Burst Hand Clap, 6-Oscillator Bronze Hi-Hats (Closed/Pedal/Open with choke groups), Crash/Splash/China Cymbals, Ride/Bell, Toms/Congas (with pitch-shifted sample interpolation across all 6 toms and 7 congas/bongos), and Cowbell/Agogo, adapting dynamically to GM Drum Kit program changes (Standard, Room, Power/Rock, Electronic/TR-808, and Jazz/Brush kits). `yamaha_fm_set_opl4_drums(false)` toggles back to pure FM/noise percussion.
- **Karaoke Library:** Compatible with the 47,998 song database extracted from SongHub (`D:\idx\shub_extracted`).
- **Synchronized Lyrics:** Multi-track SMF sequencer parses Meta Event `0x05` (Lyric) and `0x01` (Text) with syllabic delta-time synchronization. `[Music / Intro]` displays only before the first sung verse, with smooth verse transitions thereafter.
- **Audio Output:** Everest Semiconductor ES8388 Stereo Codec on I2C2 and I2S3 driving the 3.5mm Headphone Jack (CN3) via circular DMA1 Stream 5 double-buffering, plus simultaneous 12-bit analog DAC output on pin `PA4`.
- **Visual Display:** 240x240 ST7789 IPS LCD driven via STM32F407 FSMC (8080 8-bit parallel bus) featuring:
  - Real-time rolling lyric window (Previous line, Active singing line with yellow box, and verse transitions).
  - Dual stereo peak VU meters (Green $\rightarrow$ Yellow $\rightarrow$ Red).
  - Dynamic progress bar, elapsed time, and tempo (BPM).
  - Active voice polyphony HUD (`Voices: X/70`).
- **Operating Modes:**
  - **Player Mode:** Real-time synchronized lyrics and VU meter playback.
  - **Browser Mode:** Paged song selection menu with instantaneous O(1) seeking directly from `SD:/songs.idx`.
  - **Number Select Mode (Direct Song Code Entry):** Press BOTH UP + DOWN simultaneously to enter 5-digit song code entry. Use LEFT/RIGHT to move digits, UP/DOWN to scroll 0-9, and HOLD UP/DOWN or click OK to play.
  - **Audio Settings Mixer Mode:** Press BOTH LEFT + RIGHT simultaneously to open the settings view. Adjust Master Volume (0-100%), Instrument Volume (20-200%), Drum / Rhythm Volume (20-200%) and Melody / Lead Volume (20-250%) using UP/DOWN to select and LEFT/RIGHT to adjust. The lead is found automatically on each song as the MIDI channel whose notes line up with the lyric syllables; raise Melody / Lead when the vocal line is buried under the accompaniment. Values auto-save and survive both reset (via STM32 RTC Backup domain) and shutdown (via `SD:/karaoke.cfg`). Press OK to save and return.
  - **Random Play:** After every reset or power-on the player starts a random song from the catalog instead of song 1. When a song ends and no button has been pressed for 15 seconds, it starts another random one (and leaves the song browser, number entry or settings screen if one was open). A random pick skips the last 8 songs played, whether random or chosen by hand. Pausing counts as playing, so a paused song is never replaced. Build with `-DKARAOKE_BOOT_SONG=<index>` to boot into a fixed song for benchmarking.
  - **SD Self-Recovery:** One failed SD transfer used to leave the STM32 SDIO driver stuck (the DMA channel stayed claimed and FatFs kept an error on the open file), so every later read failed: tracks ended mid-note, drums and instruments vanished and notes hung. Every SD access now retries up to three times, restarting the driver (`sd_card_recover()`) and reopening the file between attempts. A song that still cannot be read stops with all notes off instead of playing on with dead tracks, and `midi_karaoke_load()` refuses a song whose lyric/melody scan failed. Build with `-DKARAOKE_STRESS_SWITCH_MS=500` to load a random song every 500 ms as a soak test; the counters `s_stress` and `s_recover_count` can be read over ST-Link.
  - **ROM Fallback:** Operates standalone with built-in embedded tracks (Bryan Adams, John Lennon, Itchyworms - Beer) even when no MicroSD card is inserted.
- **PC Searchable Songbook:** Generated `songbook.txt` (7.7 MB) formatted for quick searching in Windows Notepad (`Ctrl + F`). Contains both Numerical and Alphabetical directories.

## 3. Preparing the MicroSD Card

To generate the binary index and copy song files from `D:\idx\shub_extracted`:

```bash
# Generate curated 50-song starter package
python tools/prepare_karaoke_sd.py --limit 50 --out /path/to/sd_card

# Or index all 48,000 songs for the entire library
python tools/prepare_karaoke_sd.py --limit 0 --out /path/to/sd_card
```

Copy the generated `songs.idx` and `/midi` directory directly to the root of a FAT32-formatted MicroSD card.

**If `songs.idx` is missing or unusable** (wrong signature, version or record size, or no records), the firmware scans the card instead: `SD:/midi` and the folders directly below it, then the card root, for `.mid`/`.midi` files. Titles and artists come from file names like `027720 - Itchyworms - Beer.mid`; other names are shown by file name. Only the first 192 files found are listed, because the board has little spare RAM, so use `songs.idx` for a large library. A truncated `songs.idx` keeps the records that are present. If the card itself does not initialise (`stm32_sdmmc ... ErrorCode 0x4` at boot) there is nothing to scan, and the three built-in songs are used.

MIDI files are written one folder per thousand song codes (`midi/036/036527.mid`), so no folder holds more than 1000 files. The full library is 47,998 files in 56 folders and about 2 GB. The firmware builds the same path in `src/song_path.c` and falls back to a flat `midi/036527.mid` card if the sharded file is not found. The tool exits with an error if any song fails to copy.

## 4. Verification & Testing

### Host-Based Unit Testing (PC)
```bash
pio test -e native
```
- `test_midi_fm` re-implements the SMF header, VLQ, tempo and FM math inside the test file, so it checks the formulas, not the firmware sources.
- `test_song_path` compiles `src/song_path.c` itself and checks the SD path rule.
- `test_song_scan` compiles `src/song_scan.c` and checks file-name filtering, parsing and the path list.
- `test_catalog` compiles the real `src/karaoke_catalog.c` against a folder on the PC that stands in for the SD card (stand-ins in `test/test_catalog/`). It covers a valid, missing, corrupt, truncated and empty `songs.idx`, scanning, an unmounted or empty card, and the built-in songs.
- `test_synth` renders the real `src/yamaha_fm_synth.c` and measures pitch accuracy, decay, brightness, velocity, release, sustain pedal, pitch bend, drums, voice stealing and all 128 programs.
- `test_settings` validates non-volatile RTC backup register bit packing/unpacking, SD configuration file parsing, parameter boundary clamping, and non-inverted analog gain mapping.
- Result: **76/76 tests passing**.

### Static Code Analysis
```bash
pio check
```
- Runs Cppcheck static code analysis across all source files.
- Result: **0 defects found**.

### Building Target Firmware
```bash
pio run -e black_f407zg
```
- Compiles ARM Cortex-M4 binary with 0 warnings.
- Output binary: `.pio/build/black_f407zg/firmware.bin` (Flash: ~280 KB / 27%, RAM: ~80 KB / 61%).
